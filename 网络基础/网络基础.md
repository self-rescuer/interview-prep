# 网络基础面试题

## 1. TCP 和 UDP 的区别？各适用什么场景？

TCP 和 UDP 都是传输层协议，区别在于：

- **连接**：TCP 面向连接（先建立连接再传数据），UDP 无连接（直接发）
- **可靠性**：TCP 可靠，有确认和重传机制，保证数据完整有序；UDP 不可靠，可能丢包、乱序
- **速度**：TCP 慢（因为有确认、重传、流量控制），UDP 快
- **场景**：TCP 用于网页、文件传输、邮件等要求完整的场景；UDP 用于直播、游戏、语音通话等要求实时的场景

## 2. TCP 三次握手过程？为什么需要三次？

**过程：**

1. 客户端发 SYN 给服务器（我想连接）
2. 服务器回 SYN+ACK（收到，我也想连接）
3. 客户端再发 ACK（收到，开始吧）

**为什么需要三次：**

防止已失效的连接请求突然到达服务器。如果只有两次，服务器无法确认客户端是否收到了自己的 SYN+ACK，可能为一个已经失效的连接分配资源。三次握手保证双方都确认自己能发、能收。

## 3. TCP 四次挥手过程？为什么需要四次？

**过程：**

1. 客户端发 FIN（我说完了）
2. 服务器回 ACK（知道了）
3. 服务器发 FIN（我也说完了）
4. 客户端回 ACK（知道了，挂吧）

**为什么需要四次：**

TCP 是全双工的，两个方向要分别关闭。客户端关闭"客户端→服务器"方向后，服务器可能还有数据没发完，所以服务器要先回 ACK 表示收到，等自己数据也发完了再发 FIN 关闭另一个方向。

## 4. HTTP 和 HTTPS 的区别？

- HTTPS = HTTP + SSL/TLS 加密层
- HTTP 明文传输，HTTPS 加密传输
- HTTP 端口 80，HTTPS 端口 443
- HTTPS 需要 CA 证书，HTTP 不需要
- HTTPS 比 HTTP 更安全，但性能稍慢（加密解密有开销）

## 5. HTTPS 的加密原理？

HTTPS 用了两种加密方式配合：

- **非对称加密**：用来交换密钥。客户端和服务器各有一对公钥和私钥，公钥加密的内容只有私钥能解密，反之亦然。因为计算慢，只用来协商密钥。
- **对称加密**：用来传输数据。双方通过非对称加密协商出一个共享的对称密钥，之后所有数据都用这个密钥加密，速度快。

**流程简化版：**

1. 客户端发起连接，服务器返回公钥和证书
2. 客户端验证证书，生成一个随机密钥，用服务器公钥加密后发给服务器
3. 服务器用私钥解密，拿到对称密钥
4. 之后双方用这个对称密钥加密通信

## 6. HTTP 常见状态码及含义？

- **2xx 成功**：200 OK
- **3xx 重定向**：301 永久重定向，302 临时重定向
- **4xx 客户端错误**：400 请求参数错误，401 未认证，403 无权限，404 资源不存在
- **5xx 服务器错误**：500 服务器内部错误，502 网关错误，504 网关超时

## 7. GET 和 POST 的区别？

- **用途**：GET 获取数据，POST 创建/提交数据
- **参数位置**：GET 参数在 URL 上（`?name=张三`），POST 参数在请求体里
- **安全性**：GET 参数暴露在地址栏和历史记录里，POST 相对隐蔽
- **幂等性**：GET 是幂等的（重复执行结果一样），POST 不是（重复提交会创建多条数据）
- **缓存**：GET 可以被浏览器缓存，POST 默认不缓存

## 8. HTTP 请求和响应各包含哪些部分？

**请求：**

- 请求行：方法 + URL + HTTP 版本
- 请求头：Content-Type、Authorization 等
- 请求体：POST/PUT 时提交的数据

**响应：**

- 状态行：HTTP 版本 + 状态码 + 状态描述
- 响应头：Content-Type、Set-Cookie 等
- 响应体：服务器返回的数据

## 9. 从浏览器输入 URL 到页面显示，中间发生了什么？

1. 检查缓存：浏览器先看本地有没有缓存
2. DNS 解析：把域名翻译成 IP 地址
3. 建立 TCP 连接：三次握手
4. 发送 HTTP 请求
5. 服务器处理并返回响应
6. 浏览器渲染页面
7. 断开 TCP 连接：四次挥手

## 10. 什么是 DNS？解析过程是怎样的？

DNS 是互联网的"电话簿"，把域名翻译成 IP 地址。

**解析过程：**

1. 浏览器先查自己的缓存
2. 没有就查操作系统的 hosts 文件和 DNS 缓存
3. 再没有就问本地 DNS 服务器（通常是运营商提供的）
4. 本地 DNS 服务器逐级向上查询：根域名服务器 → 顶级域名服务器（.com）→ 权威域名服务器（baidu.com）
5. 拿到 IP 后返回给客户端，并缓存起来

# 项目结合题

## 11. 你在 django-crm 接口测试中，怎么断言 HTTP 状态码？

我在 `AssertUtils` 工具类里封装了 `assert_status_code` 方法：

（下面这个代码块用四个空格缩进，避免和外部嵌套冲突）

    @staticmethod
    def assert_status_code(response, expected_code):
        actual = response.status_code
        assert actual == expected_code, \
            f"状态码错误：期望 {expected_code}，实际 {actual}"

测试用例里调用：`AssertUtils.assert_status_code(response, 200)`

好处是失败信息里同时显示期望值和实际值，方便定位问题。

## 12. 你的接口测试框架里，重试机制怎么设计的？为什么需要？

在 `RequestClient._request` 方法里加了重试循环：

    def _request(self, method, path, retries=3, **kwargs):
        for attempt in range(1, retries + 1):
            try:
                response = requests.request(method, url, headers=headers, **kwargs)
                return response
            except Timeout:
                self.logger.warning(f"第 {attempt} 次请求超时")
            except ConnectionError:
                self.logger.warning(f"第 {attempt} 次请求连接失败")
            if attempt < retries:
                time.sleep(1)
        raise Timeout(f"请求重试 {retries} 次后仍失败")

**为什么需要重试：** 网络抖动是偶发问题，不是业务逻辑错误。如果因为一次超时就让测试失败，会产生大量误报。重试 3 次能过滤掉偶发的网络问题，提高测试稳定性。但如果是服务器持续不可达，重试完还是失败，测试应该报错。
